# 提示詞房間

三語版本的提示詞各自獨立成檔（中文提示詞未必比英文差、日文版用日文也未必差），
但後端程式碼要分好房間，語言之間不互相干擾。

---

## 隔離的邊界畫在哪裡

```
每個語言一個檔，完全獨立            只有一份，跟語言無關
──────────────────────────         ─────────────────────────
zh.yaml   中文 system 指示           cost_engine        算錢
en.yaml   英文 system 指示           success_predictor  算成功率
ja.yaml   日文 system 指示           constraint_engine  物理約束
          提示詞寫作規則              casting            選角關卡
          給模型的範例                project            狀態機
```

**改 `ja.yaml` 不會影響 `zh.yaml`**，這就是互不干擾。

但算錢的邏輯只有一份 —— 否則會出現「日文版算出來的價格跟中文版不一樣」，
那是比「檔案混在一起」嚴重得多的問題。

判準：**「換個語言就要換寫法」的東西進房間，「換個語言結果應該一樣」的留在外面。**

---

## 介面語言 ≠ 提示詞語言

這是兩個獨立的選擇，不要綁死：

| | 是什麼 | 誰在用 |
|---|---|---|
| **介面語言** | 使用者看到的文字 | 人 |
| **提示詞語言** | 餵給 Veo / Gemini 的描述 | 模型 |

一個台灣編劇可能用**中文介面**，但拍動畫風時選**日文提示詞** ——
因為「間」「余白」「作画」這些概念，日文比英文精確。

預設關聯（可覆寫）：
- `anime` 風格 → 建議日文提示詞
- 其他風格 → 建議與劇本原文同語言

---

## 「哪種語言的提示詞效果最好」目前是**假設，不是結論**

「Veo 對英文指令服從度較高」是沿用業界說法，沒有經過本專案自己的實測。

要驗證的話：同一個鏡頭用三種語言各生一次，
比較構圖準確度、風格貼合度、失敗率。成本約 $0.60。

在做完那個實測之前，UI 上不要宣稱哪種語言比較好，
只提供選擇並說明「不同語言各有擅長的表達」。

## 檔案結構

每個語言檔的頂層鍵：

```yaml
meta:              語言代碼、名稱、寫作慣例摘要
agents:
  script_parser:   system_instruction / user_template
  shot_planner:    system_instruction / user_template
  prompt_writer:   visual_prompt 該怎麼寫的規則
ui:                介面文案（按鈕、標題、提示）
```

新增語言 = 複製一個檔改內容，不用動任何 code。
